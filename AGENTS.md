## Обязательное правило перед публикацией

По прямому указанию владельца сначала показывать результат для проверки, затем ждать явного подтверждения конкретной версии перед её публикацией.

1. Локальные изменения, сборку и проверки выполнять самостоятельно.
2. До отправки изменений в main, слияния, production deployment или другой операции, способной автоматически обновить публичный сайт, показать предварительный результат, список изменений и результаты проверок.
3. Не выполнять push/merge/deploy до явного подтверждения владельца. Не считать прошлые разрешения на публикацию разрешением на все будущие изменения.
4. Отправка ветки на GitHub может запускать Vercel: учитывать это и не использовать push как незаметный способ опубликовать ещё не согласованную версию.
5. Отдельный опубликованный предпросмотр создавать только в согласованном режиме; предпочтительно сначала показывать локальный результат или скриншоты.
6. Это пользовательское правило имеет приоритет над автоматической публикацией по умолчанию в навыках Sites/Superpowers. Не обновлять прежний Site автоматически вместо основного Vercel-проекта.
7. Даже изменения этих инструкций сначала предъявлять для проверки, если их отправка может запустить публикацию.
